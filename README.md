# Human Performance OS 本地 MVP

版本 0.5.4 · 2026-10-16。题库包含72道判断题、15篇记忆材料和25个表达主题，日常训练优先未练内容，基线题组单独固定。凌晨入睡日期自动联动，仍可手动指定。新任务采用系统评分，表达只使用文字输入。驾驶舱首页采用独立仪表、趋势与行动区、五系统状态带；沿用现有数据、组件和记录流程。无需账号；记录均保存在当前浏览器，历史录音可继续回放、下载和删除。

## GitHub Pages

项目仓库：[1337m4n/human-performance-os](https://github.com/1337m4n/human-performance-os)。站点地址：[health.1337m4n.beer](https://health.1337m4n.beer/)。

推送到 main 后，GitHub Actions 安装锁定依赖、运行核心自检、构建并发布 dist。Pages 发布来源使用 GitHub Actions，自定义域名在仓库 Pages 设置中绑定 health.1337m4n.beer；DNS 的 health CNAME 指向 1337m4n.github.io，证书就绪后启用 Enforce HTTPS。使用 GitHub 自带的发布令牌，无需个人令牌或服务器。

发布内容只有静态程序，健康记录与录音保存在访问者自己的浏览器。线上域名和本地地址属于不同数据空间：迁移文字记录前，先在旧地址导出 JSON，再在新地址导入；录音需在旧地址单独下载，当前不支持录音文件上传恢复。电脑与手机也不会自动同步。

## 直接使用

本地交付包包含已构建的 dist；GitHub 源码仓库不提交 dist，从仓库下载或克隆后需先运行下方的 npm ci 和 npm run build。

macOS 双击本目录的 `启动.command`。它使用 Python 3 启动已构建的静态文件，并打开 [本地入口](http://127.0.0.1:5183/)。关闭终端或按 Control+C 结束服务。已确认当前电脑有 Python 3。

也可以在本目录运行：

```sh
python3 -m http.server 5183 --bind 127.0.0.1 --directory dist
```

请保持使用同一个浏览器及完整地址 `http://127.0.0.1:5183`。改成 localhost、不同端口、不同浏览器或清理浏览器数据，会进入另一个数据空间或失去记录。建议定期从设置导出。新任务不启用录音或麦克风。

首次进入个人初始化，默认没有模拟成绩。演示入口及各页面始终标注模拟空间，两套数据库分离。

## 持久层与备份

内部记录保留原型的页面投影，以减少已有交互的改动；`model.js` 在写入和导入边界校验，并在导出/恢复时映射到 `model.ts` 的核心实体。旧版缺少真实计时/输入设备条件的训练保留原始成绩，但标注并排除比较；时间、实际秒数及准备时间缺失保留null，设备输入未知使用unknown。对应核心类型扩展了这些可空字段，优先遵循PRD的缺失数据规则，不补造计时或鼠标输入。内部 schemaVersion=2；规范导出 schemaVersion=1，format=human-performance-os-core；数据库结构版本为1。这三个版本的用途不同。

`hp-os-local-personal` 与 `hp-os-local-demo` 各有 workspace、audio、drafts、backups。单用户小型历史采用一份原始记录快照，训练结果、待办、计划引用、音频与对应草稿清理在同一事务提交；没有单独复制的图表成绩。数据明显增大时再迁移为逐实体store及索引。

同一网址下原型v1的文字键和音频库可自动迁移。新事务成功前不删除原版；迁移前保存原始JSON和含音频的本地快照。不兼容版本保留原文件，可导出后显式恢复。跨网址需要先从原版导出JSON，再在新版导入。

JSON保留原始项、时间、时区、来源、协议、关联ID和音频元数据，**不包含录音二进制**。同一浏览器现有且ID匹配的音频可在恢复时保留；换网址或设备需要事先单独下载录音，当前没有音频文件上传恢复。CSV单元格防公式注入。

恢复前先校验，再列出条数确认，并保留一个当前数据的本地快照。只保留最近一个快照。逐条删除同时清理快照中的对应记录/录音副本；清空同时删除记录、设置、计划、草稿、复盘、快照和录音。浏览器本地存储不是自动异地备份或设备级加密。

## 实际限制

- 内置72道原创判断题、15篇虚构记忆材料、25个表达主题，是有限题库；用完后按最久未练优先复习。未进行题目难度等值校准或效度验证。固定基线与日常抽题分开，记忆按材料分别比较，重复材料只表示练习。
- 没有跨设备同步、账号、AI诊断、语音转写、自动到期通知或穿戴设备。关闭页面后需主动返回继续延迟回忆。
- 浏览器验证使用Chrome隔离上下文及合成麦克风；尚未验证 Safari/Firefox及真实读屏器；新任务已取消录音。200%为等效CSS视口验证，未覆盖所有浏览器缩放组合。
- 夏令时重复的本地时刻采用较早一次；不存在的本地时刻阻止写入。需要精确指定重复小时的另一时刻时，可使用完整ISO时间戳的JSON补记。
- 这些任务与分组只是自我观察，未通过临床或生产安全认证，不能据此判断智商、疾病或因果。

## 0.4.0 系统评分规则

- 文字表达：组织、依据与行动、文字连贯度分别采用5条公开条件，满足一条得1分，范围0–5。每项展示命中依据和下一条改进方向。维度借鉴 AAC&U Written Communication VALUE Rubric，但本地规则仅检查文本特征，不复刻正式 rubric 的0–4级评估，也不判断语义真假或声音流畅度。来源：https://www.ubalt.edu/_migrated-binaries/ubalt.edu/institutional_effectiveness/uploads/documents/assessment_handbook/written%20communication.pdf
- 记忆：每份材料6个信息单元，各单元必要事实匹配完整得1分。使用固定材料的关键词、部分同义表达及关系检查；未识别的事实计0分，不让用户自行勾选。该方法可能漏掉未收录的转述，未做临床效度校准。借鉴信息单元评分思路：https://pmc.ncbi.nlm.nih.gov/articles/PMC4532931/
- 运动：依据观察到的说话情况自动判定有氧强度；能说话不能唱歌归为中等强度，只能说几个字归为高强度，未知不默认推算。力量训练仍按训练日期计天。来源：https://www.cdc.gov/physicalactivity/basics/measuring/index.html
- 睡眠、调节和营养：删除主观数字评分入口，收集起止时间、清醒分钟、活动事实、饮水和文字感受；自动计算时长、个人目标差距、起床波动、记录覆盖和完成进度，不把压力、疲劳或精力文字转换成伪客观健康分数。睡眠记录思路参考：https://www.nhlbi.nih.gov/resources/sleep-diary
- 周复盘自动生成统计快照与等长窗口对比；工作例子和下周调整均可留空。旧自评、自核对及录音保留，系统分与旧分按协议及规则来源分开比较。JSON保留新评分版本、来源和原始文本；导入会校验系统分与规则结果是否一致。

## 0.5.0 题库与版本

`src/training-bank.js`保存新增题目、答案、解析、材料信息单元规则及表达关键词。发布过的ID、题干、答案和规则不原地改写；勘误另建版本，避免历史分数重算。判断常规训练使用judge-v2/judge-bank-v1，基线保留judge-v1。表达新增text-rules-v2以覆盖扩展主题，text-rules-v1按原规则校验与展示。旧记录、录音和备份继续可用，新旧条件分别观察。

空的介绍页草稿不锁题；非空草稿保留，基线和日常草稿分开。记忆轮换优先避开待延迟材料，再次阅读时标注重读。睡眠日期默认按起止时刻推算，手动改日期会关闭自动模式；编辑旧记录默认保留原日期，真实超24小时仍需确认。

0.5.1边界修复：训练等待草稿读取完成，保存期间停止自动草稿写入；换主题前确认清空旧文字，恢复草稿保留目标时长。修改备注保留导入记录的全部力量训练和咖啡因明细。单项力量组数可修改并保留次数、重量；多项明细尚无逐项编辑表单，汇总字段改动会阻止保存，避免覆盖原明细。

0.5.2逻辑修复：时间戳按真实时刻排序，避免UTC与带偏移格式混用时选错最新记录或睡眠配对；同日最近记录按创建时间倒序。睡眠目标差距只取夜间睡眠，最近调节进度只取计时练习。写入与恢复时逐项校验调节时长、力量明细、全部咖啡因及历史精力条目；延迟回忆必须关联同材料即时会话，到期时间晚于阅读时间，待办不得重复。计划、复盘和观察周期日期无效时拒绝恢复，保留当前数据。

0.5.3会话修复：专注和调节结束后的文字由同一份状态保存，点击保存或确认离开均保留备注。专注结束时固定结束时刻，填写备注不计入暂停。延迟回忆在到期、草稿读取完成后开始，实际间隔截至回忆开始，作答时间单独记录；等待期间不产生回忆草稿。恢复未完成的回忆时保留原文及系统评分，标记中断并将不确定的实际用时留空，不进入可比趋势，避免跨日草稿因时长超限无法保存。

0.5.4按共享约束加固：复盘指标与引用、文本/布尔类型、专注状态和固定观察窗口均在数据入口校验；非法计划日期处理不会修改全局对象。延迟待办保留备份前的ID，完成状态由正式回忆结果推导；固定判断题组的任务定义始终保留6题。仪表数值、样本数及折线使用一致的可比分组和记忆阶段。换题及保存未结束时锁定后续操作；未知练习参数使用默认练习，专注分钟遵守整数步进。

草稿使用同页顺序队列和跨页乐观校验。正式保存先等待本页已提交的草稿写入，再在同一事务内核对、删除草稿并写入结果；冲突时整个事务失败，另一页的草稿和当前输入均保留。发生冲突时先复制当前输入，再刷新读取最新草稿。JSON保留规范记录，不包含尚未保存的草稿；新增的延迟待办ID字段为可选字段，旧备份继续兼容。
